기능이 많아도 처음부터 모든 화면을 볼 필요는 없습니다. 필드의 뜻을 알고 싶으면 필드 설명, 다른 값과의 관계를 보려면 관련 값, 제품을 검토하려면 체크리스트 → 제품 검토 순서로 사용하세요.

현재 조건을 볼 때는 필드의 ‘확인 조건’ 탭을 우선 사용하세요.

‘전체 필드 재점검 내역’과 ‘NVMe 보완 내역’에는 이전 편집 내용이 남아 있습니다. 이 화면의 삭제·추가 개수나 이전 문구는 현재 검토 조건 또는 제품 결과와 다릅니다. 구분 방법은 9번 항목에 정리했습니다.

1. 처음 사용할 때

  1. output/id_ctrl_ko.html을 브라우저로 엽니다.

    설치나 서버가 필요하지 않습니다. HTML에 내장된 설명·검색·관계·기록 기능은 인터넷 없이 사용할 수 있습니다.

  2. 상단에서 연결 방식과 controller 유형을 선택합니다.

    일반 PCIe SSD는 ‘PCIe / memory-based’와 ‘I/O controller’를 출발점으로 삼고, 실제 검토 대상에 맞게 조정합니다.

  3. 왼쪽 검색으로 필드를 찾습니다.

    예: VWC, 전원, 77, 0x4D. 오프셋 검색은 해당 byte를 포함하는 필드를 찾습니다.

  4. ‘필드 설명 → 관련 값 → 확인 조건’ 순서로 읽습니다.

    필요하면 ‘대응 원문’을 펼쳐 한국어 설명과 연결된 영문을 비교합니다.

  5. 제품 결과를 남길 때만 프로젝트를 만듭니다.

    설명만 읽는 경우 프로젝트는 필요하지 않습니다. 기록을 만들었다면 ‘기록 반영’ 후 ‘JSON 저장’까지 진행하세요.

휴대전화처럼 화면이 좁으면 상단 ‘목록’ 버튼으로 왼쪽 탐색 목록을 엽니다.

3. 필드 설명 읽기

필드 설명

바이트 위치·인코딩·단위·비트·해석 안내·영문

관련 값

직접 연결된 항목의 관계도와 전체 관계표

확인 조건

적용 조건·관측값·요구 관계·예외·근거

  • 왼쪽 ‘Identify 필드 / 관련 규정 / 전체’로 검색 대상을 선택합니다. 관련 규정이 검색되지 않으면 이 선택부터 확인하세요.
  • ‘오프셋 순 / 주제별’로 목록 순서를 바꾸고, 주제 필터로 범위를 좁힐 수 있습니다.
  • 예약 영역은 기본 목록에서 숨겨집니다. 필요하면 ‘예약 영역도 표시’를 켭니다.
  • ‘관련 값’의 관계도에는 직접 연결 중 최대 8개가 보입니다. 더 많은 연결은 아래 표에서 확인하세요.
  • 관계도 노드나 표의 항목을 누르면 같은 도구 안에서 이동합니다. 브라우저의 뒤로 가기로 돌아옵니다.
  • ‘정방향 / 역방향’은 참조 연결의 방향입니다. 값이 영향을 주는 방향이나 데이터 전송 방향으로 단정하지 않습니다.
지원 능력과 현재 설정은 구분해서 읽습니다. 예를 들어 VWC의 캐시 속성과 Feature의 캐시 활성화 설정이 연결되어 있어도, 설정 변경이 Identify 지원 능력 변경을 뜻하는 것은 아닙니다.

상단 ‘직접 링크 복사’로 현재 필드·탭·조건의 위치를 공유할 수 있습니다. 받는 사람도 같은 HTML 파일이 있어야 합니다. 파일 경로가 다르면 주소의 # 뒤 부분을 받는 사람의 HTML 주소에 붙입니다.

4. 적용 설정

설정사용 방법
TransportPCIe / memory-based 또는 Fabrics를 선택합니다. 실제 연결 방식에 맞춥니다.
Controller 유형I/O, Administrative, Discovery 중 대상 유형을 선택합니다. 유형에 따라 필수·선택·예약 해석이 달라집니다.
기준 문서‘검토 적용 설정’을 펼쳐 NVMe + OCP / NVMe / OCP 표시 범위를 고릅니다. 문서 버전을 바꾸는 기능이 아닙니다.
OCP 적용미확인 / 적용 / 미적용 중 선택합니다. ‘미적용’만으로 기존 결과가 자동으로 ‘적용 제외’가 되지는 않습니다.
DP-CFG-1~11고객이 선택한 A/B를 항목별로 입력합니다. 전체 제품에 하나의 A 또는 B를 일괄 적용하는 선택이 아닙니다. 자료가 없으면 미확인으로 둡니다.

설정은 설명의 적용 범위를 판단하는 자료입니다. 전체 필드를 자동으로 제거하거나 장치 값을 판정하지 않습니다. 현재 필드가 보인다고 그 controller에서 사용 가능한 필드라는 뜻도 아닙니다.

제품 프로젝트가 열려 있으면 적용 설정도 JSON에 포함됩니다. 관련 설정이 바뀐 기존 기록은 ‘재확인 필요’로 표시될 수 있습니다. 문서 표시 필터만 바뀌는 것은 제품 값 변경이 아닙니다.

5. 확인 조건과 근거 읽기

  1. 적용 조건부터 확인합니다.

    어떤 기능·controller·상태·OCP 항목별 설정일 때 요구되는지 확인합니다. 알 수 없다면 적용 여부도 미확인입니다.

  2. ‘확인할 값’을 모읍니다.

    Identify뿐 아니라 Feature·Log·레지스터·namespace 값 등이 필요할 수 있습니다. 이 도구가 장치에서 값을 읽어 주지는 않습니다.

  3. ‘요구 관계·동작’을 비교합니다.

    단순한 정의·단위 안내와 값 사이의 제약·명령 요구를 구분합니다. SHALL / SHOULD / MAY는 각각 필수 / 권고 / 허용의 수준입니다.

  4. 예외와 대응 원문을 확인합니다.

    ‘대응 원문’을 펼친 후 목록에서 원문 조각을 고릅니다. 연결 후보가 포함된 조건은 한국어와 원문을 직접 대조합니다.

  5. 자료가 충분할 때 제품 결과를 기록합니다.

    원문 해석이나 적용 설정이 아직 불명확하면 이유를 남기고 판단 보류합니다.

화면에 나오는 두 종류의 상태

구분무엇을 뜻하나표시 예
콘텐츠 확인 상태문서의 설명·해석·근거를 얼마나 대조했는지 나타냅니다.미검토, 원문 대조 완료, 해석 확인 필요, 원문 불일치, 외부 근거 필요
제품 검토 결과사용자가 특정 제품·firmware·controller/namespace에 대해 기록한 판단입니다.미검토, 조건 만족, 조건 위반, 판단 보류, 적용 제외
‘원문 대조 완료’는 제품이 조건을 만족한다는 뜻이 아닙니다. 반대로 제품 결과를 기록해도 설명의 원문 대조 상태는 바뀌지 않습니다. 모든 설명과 예외가 대조 완료된 상태는 아닙니다.

‘원문 대응’ 화면의 등록 수는 원문과 콘텐츠의 연결 수입니다. 의미 대조 완료 수와 구분해서 봅니다. 고유 조건은 공유 규정을 한 번씩 센 수, 검토 대상은 PSD 등 대상별 조건 수, 필드 연결은 각 필드에 연결된 수입니다.

출처에는 문서 버전·절·Figure·인쇄 페이지·PDF 페이지가 표시됩니다. SHA-256은 사용한 파일을 구별하는 값입니다. ‘PDF 위치’ 링크는 HTML 상위 폴더에 대응 PDF가 있을 때 열리며, 일부 브라우저에서는 지정 페이지 대신 문서 첫 화면을 열 수 있습니다.

6. 작업별 체크리스트

필드 이름을 모두 알지 못해도 작업을 선택해 시작할 수 있습니다. 각 작업은 적용 설정 → 필요한 자료 → 확인 순서 → 조건 목록 → 미확인 사항 순서로 구성되어 있습니다.

작업주요 검토 대상
식별 정보 대조 ↗VID·SSVID·Serial·모델·firmware·FGUID와 외부 식별 정보
펌웨어 업데이트 ↗슬롯·다운로드 단위·활성화·보존 상태
전원 관리 ↗NPSS·PSD·Power Management·APST
쓰기 원자성 ↗Controller/namespace의 원자성 보장·경계·설정
전송 크기 ↗MDTS·페이지 크기·metadata·명령별 제한
OCP 요구 검토 ↗NVMe 조건과 OCP 추가 요구·A/B 선택·예외

조건 본문은 필드 상세와 같은 고정 ID를 참조합니다. 같은 ID가 여러 작업에 나오는 것은 공유 조건을 여러 관점에서 보는 것입니다. PSD 공통 규정은 PS 번호별 검토 대상과 구분하세요.

  • CSV 내보내기: 현재 문서 표시 범위의 체크리스트 조건을 표로 저장합니다. 제품의 판정 결과를 내보내는 버튼은 제품 검토 화면의 ‘CSV 보고서’입니다.
  • 인쇄: 브라우저 인쇄 창에서 종이 또는 PDF 저장을 선택합니다. 펼친 원문을 제외하면 조건 위주로 인쇄할 수 있습니다.
  • 단위 환산 예제: MDTS와 0 기반 LBA 개수를 환산합니다. 비어 있는 입력은 0으로 취급하지 않습니다. 결과는 설명용이며 metadata·명령별 제한까지 자동 판정하지 않습니다.

7. 제품별 수동 검토 기록

  1. ‘제품 검토 → 새 프로젝트’를 선택합니다.

    제품명·모델·Serial·Firmware·검토 대상 controller·검토자를 입력합니다. 제품명과 Firmware를 모르면 ‘미확인’이라고 명시합니다.

  2. 같은 탭에서 원하는 조건으로 이동합니다.

    체크리스트 또는 필드의 ‘확인 조건’에서 ‘수동 검토 기록’을 누릅니다. 다른 탭의 프로젝트와 자동으로 공유되지는 않습니다.

  3. 관측값과 대상을 적습니다.

    예: controller-0 / NSID 1, 값과 단위, reset 전후 상태, 실제 관측 날짜, 덤프·캡처 파일명. 시점과 상태는 초기값 ‘미확인’에서 필요한 값으로 변경합니다.

  4. 결과와 이유를 직접 선택해 ‘기록 반영’을 누릅니다.

    입력만 하고 이동하면 반영되지 않습니다. ‘기록 반영’은 현재 열린 프로젝트 메모리에 넣는 동작입니다.

  5. 프로젝트 화면으로 돌아가 ‘JSON 저장’을 누릅니다.

    반영한 결과도 JSON 파일을 내려받기 전에는 브라우저 안에만 있습니다. 다운로드된 파일을 확인하세요.

결과선택 기준과 필요한 입력
미검토아직 비교하거나 판단하지 않았습니다.
조건 만족적용되는 요구를 만족한다고 직접 판단했습니다. 관측값·검토자가 필요합니다.
조건 위반적용되는 요구를 위반한다고 직접 판단했습니다. 관측값·검토자가 필요합니다.
판단 보류자료·원문 해석·적용 범위 등이 부족합니다. 이유와 검토자가 필요합니다.
적용 제외이 검토 대상에는 조건이 적용되지 않는다고 직접 판단했습니다. 이유와 검토자가 필요합니다.

예를 들어 SSVID를 검토한다면 Identify 값과 PCI Header 값을 수집하고, ‘현재 운영 / 2026-10-12 14:00 KST / identify.txt, pci-header.txt’처럼 실제 관측 정보를 기록합니다. Header 자료가 없다면 ‘PCI Header 미수집’을 이유로 판단 보류합니다. 예시 날짜·값을 실제 관측값으로 사용하지 않습니다.

  • 미검토 이외의 결과를 기록하면 제품명·모델·Serial·Firmware 수정이 잠깁니다. 다른 제품·firmware는 새 프로젝트로 만듭니다.
  • Controller와 관측 대상은 별도로 구분됩니다. 서로 다른 controller의 ‘NSID 1’은 별도 기록입니다.
  • 같은 조건·controller·관측 대상의 결과를 수정하면 현재 결과는 갱신되지만 이전 결과와 관측값은 이력에 남습니다.
  • 조건 의미·의무 수준·근거가 개정되거나 관련 적용 설정이 바뀌면 기존 결과에 ‘재확인 필요’가 표시될 수 있습니다. 결과가 자동으로 위반으로 바뀌지는 않습니다.
  • 현재 문서에서 삭제된 조건도 과거 기록과 당시 조건·제품 정보를 보존합니다.

8. 저장·공유·다음에 이어서 보기

보관 원본은 프로젝트 JSON입니다. CSV나 인쇄본에서 프로젝트를 복원할 수 없습니다. 브라우저 저장소에도 자동으로 보관하지 않습니다.
기능저장되는 내용 / 용도
기록 반영현재 열린 프로젝트에 결과·관측값·이력을 반영합니다. 디스크 파일 저장은 별도로 해야 합니다.
JSON 저장제품 정보·적용 설정·관측값·결과·변경 이력을 내보냅니다. 다음 검토의 보관 원본입니다.
JSON 가져오기내보낸 프로젝트를 엽니다. 현재 프로젝트와 병합하지 않습니다. 오류가 있으면 현재 작업은 유지됩니다.
CSV 보고서조건별 결과·관측값·이유·근거 파일명·검토자·재확인 표시를 표로 내보냅니다.
인쇄현재 프로젝트 결과 목록 등을 브라우저 인쇄 기능으로 출력합니다. 전체 규격 인증 결과를 뜻하지 않습니다.

다시 시작하는 순서

HTML 열기 → 제품 검토 → JSON 가져오기 → 제품과 Firmware 확인 → 재확인 표시 확인 → 검토 계속 → JSON 저장.

프로젝트와 근거 파일 보관 예

제품A_FW1_검토/ review-20261012.json 프로젝트 보관 원본 review-report.csv 공유용 결과표 identify-before.txt 실제 수집한 근거 pci-header.txt 실제 수집한 근거 memo.txt 추가 설명

근거 입력란에는 파일명·설명만 들어갑니다. 실제 덤프·캡처 파일은 JSON에 포함되지 않으므로 함께 보관하거나 전달하세요. 새 프로젝트를 열기 전, 가져오기로 교체하기 전, 새로고침하거나 브라우저를 닫기 전에 저장합니다.

이 설명서의 ‘참조 도구 열기’ 링크는 새 탭을 엽니다. 기존 탭에서 작성 중인 프로젝트가 있다면 그 탭에서 계속 작업하세요. 새 탭은 기존 탭의 메모리 상태를 이어받지 않습니다.

현재 도구에는 설명·검토 기능 외에 편집 과정의 기록도 보존되어 있습니다. 비슷한 이름의 페이지가 보여도 목적이 다릅니다.

이전 편집 페이지의 ‘삭제한 조건’이 보인다고 그 문구가 현재 조건으로 유지되는 것은 아닙니다. 현재 필드의 ‘확인 조건’과 고정 조건 ID를 기준으로 확인하세요. 설명이 서로 다르면 원문을 대조하기 전까지 판단 보류로 남깁니다.

콘텐츠를 직접 수정하는 사람을 위한 파일 구분

source/catalog.json이 콘텐츠 편집 원본입니다. content.json과 output/id_ctrl_ko.html은 python build.py로 생성됩니다. 과거 Python 편집 모듈은 이관 기록이며 수정해도 현재 콘텐츠에 반영되지 않습니다.

이 설명서의 편집 원본은 source/user_guide.html, 열람 파일은 output/user_guide.html입니다. 빌더는 설명서도 함께 복사합니다.

10. 자주 헷갈리는 부분

‘등록된 조건 없음’이면 확인할 것이 없나요?
현재 등록된 조건이 없다는 뜻입니다. 원문 검토 후 조건이 없음을 확인했다는 뜻은 아닙니다. 필드 정의·비트·적용 범위·후속 근거를 확인하세요.
‘해석 확인 필요’인데 결과를 기록할 수 있나요?
기록할 수 있지만 결과는 사용자의 판단입니다. 대응 원문 후보와 예외를 대조하고, 해석이 해결되지 않았으면 판단 보류로 이유를 남기는 것이 적절합니다.
프로젝트를 저장했는데 덤프 파일이 없어요.
프로젝트에는 파일명·설명만 저장됩니다. 실제 파일은 별도로 보관하세요. ‘기록 반영’만 눌렀다면 프로젝트 JSON도 아직 저장되지 않았습니다.
JSON을 가져왔는데 이전 프로젝트와 합쳐지지 않아요.
가져오기는 별도 프로젝트를 여는 기능입니다. 병합 기능은 없습니다. 현재 프로젝트를 JSON으로 저장한 다음 다른 파일을 여세요.
PDF 링크가 열리지 않아요.
HTML이 output 폴더에 있고, 원래 이름의 PDF들이 그 상위 폴더에 있는지 확인하세요. HTML만 옮기면 내장된 설명과 원문 조각은 읽을 수 있지만 로컬 PDF 링크는 끊길 수 있습니다.
OCP 미적용으로 선택했는데 조건이 계속 보여요.
적용 설정은 자동 제외 판정이 아닙니다. 문서 표시 범위를 NVMe로 바꾸어 OCP 조건을 숨기거나, 제품 검토에서 조건이 실제로 비해당인지 확인하고 이유와 함께 적용 제외를 기록하세요.
전체보기의 색상이나 조건 수가 제품 합격 여부인가요?
색상은 조건 분류, 숫자는 등록된 조건·검토 대상·필드 연결의 집계입니다. 제품 합격률이나 전체 NVMe/OCP 인증 결과가 아닙니다.
외부 자료는 모두 확인된 상태인가요?
문서 확보와 규정 대조 완료는 별개입니다. ‘원문 대응’의 상태를 확인하세요. IEEE OUI 등록 목록은 현재 미확보이며, 조회하지 못한 값을 미할당으로 판단하지 않습니다.
이 문서는 2026-10-12의 화면과 동작을 기준으로 작성한 사용 설명서입니다. 규정의 판단 근거는 개별 조건의 원문·출처·확인 상태에서 확인합니다. 설명서의 링크는 같은 폴더의 id_ctrl_ko.html을 새 탭으로 엽니다.
