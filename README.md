# CNS 01h 참조·수동 검토 도구

한국어 NVMe Identify Controller 참조 및 제품별 수동 검토용 오프라인 도구입니다.

## GitHub에서 내려받아 사용하기

저장소의 **Code → Download ZIP**으로 내려받아 압축을 풀고, `output/user_guide.html` 또는 `output/id_ctrl_ko.html`을 브라우저로 엽니다. GitHub 파일 화면은 HTML을 앱처럼 실행하지 않으므로 로컬에서 여세요.

원본 규격 PDF, 전체 페이지 추출 캐시, 보조 `nvme.h`, 장치 덤프와 프로젝트 검사용 예제는 저장소에 포함하지 않습니다. 내장 콘텐츠 열람과 카탈로그 재생성에는 PDF가 필요하지 않습니다. 전체 PDF 링크를 사용하려면 각 문서의 원본 파일을 직접 확보해 저장소 최상위 폴더에 원래 파일명으로 둡니다.

원문·그림·상표의 권리는 각 규격 발행 기관에 있습니다. 이 도구는 공식 규격 문서나 인증 결과를 대체하지 않습니다. 원문 해석·예외 대조의 미완료 항목은 콘텐츠 확인 상태로 구분합니다.

`output/id_ctrl_ko.html`을 브라우저로 엽니다. 열람·검색·관계 탐색·체크리스트·제품 프로젝트 저장/가져오기는 인터넷이나 서버 없이 동작합니다.

사용 설명서는 `output/user_guide.html`입니다. 도구의 상단 **사용 안내 → 사용 설명서 열기**에서도 열 수 있습니다. 설명서 편집 원본은 `source/user_guide.html`이며 빌더가 열람 파일을 함께 생성합니다.

## 사용 순서

1. **원문 대응**에서 등록 상태와 대조 완료 상태를 구분해 확인합니다. 전체 152개 byte 범위를 등록했으며, 미대조 문구는 확인 대기입니다. 등록 개수는 정확성 확인이나 장치 검증 완료 수가 아닙니다.
2. 필드를 선택하면 **필드 설명 / 관련 값 / 확인 조건** 탭이 표시됩니다. 비트 정의와 단위 안내는 설명에, 실제 제약은 조건에 있습니다.
3. **체크리스트**에서 식별 정보·firmware·전원·원자성·전송 크기·OCP 작업을 선택합니다. 공유 조건을 참조하며 필요한 자료·순서·조건·미확인 사항을 제공합니다.
4. **제품 검토**에서 제품·firmware별 프로젝트를 만듭니다. 관측값과 근거 파일명은 직접 입력하고 결과도 직접 선택합니다.
5. 기록을 반영한 후 프로젝트 화면에서 **JSON 저장**으로 내보냅니다. JSON이 보관 원본이며 브라우저 저장소는 사용하지 않습니다.

## 적용 설정과 링크

- 상단 controller·transport 및 펼칠 수 있는 적용 설정에서 기준 문서·OCP 적용 여부·DP-CFG-1~11의 항목별 A/B를 선택합니다.
- 미확인 설정을 비해당으로 처리하지 않습니다. OCP를 미적용으로 선택해도 결과는 사용자가 직접 적용 제외 여부를 판단합니다.
- 기존 `#VWC` 링크는 유지됩니다. 탭 링크는 `#VWC%3Fview%3Dchecks`, 조건 링크는 고정 condition ID를 사용합니다.
- `#coverage`: 원문 대응, `#workflows`: 작업 목록, `#project`: 제품 검토.
- 필드 목록에서 약어·한국어·영문·offset·조건 ID를 검색할 수 있습니다.
- SVG 관계도는 직접 연결 중 최대 8개를 표시하고, 전체 연결은 표로 제공합니다. 연결이 있다는 이유로 Identify 값 변경을 의미하지 않습니다.

## 제품 검토 기록

- 결과: 미검토 / 조건 만족 / 조건 위반 / 판단 보류 / 적용 제외. 마지막 두 결과에는 이유가 필요합니다.
- 관측값에는 controller/namespace 대상, 값·단위, 관측 날짜·상태, 근거 파일명을 입력합니다. 여러 관측값은 줄별로 적을 수 있습니다.
- 관측 상태는 공장 출하·현재 운영·변경 전후·reset 전후·firmware activation 전후를 구분합니다.
- 같은 조건이라도 대상이 다르면 결과를 별도로 기록합니다. PSD는 공유 템플릿과 PS별 검토 대상을 구분합니다.
- 변경 전 결과·관측값은 이력에 남습니다. 조건 의미·의무 수준·근거가 바뀌면 revision이 달라져 재확인이 필요하다고 표시합니다.
- 삭제된 조건의 과거 결과와 당시 조건·제품 정보도 보존합니다.
- 결과를 기록한 제품의 제품명·모델·Serial·firmware는 잠깁니다. 다른 제품·firmware는 새 프로젝트로 만드세요. controller·검토자는 변경할 수 있습니다.
- JSON 가져오기는 현재 프로젝트와 병합하지 않습니다. 형식이 잘못되면 현재 작업을 유지합니다. 지원 형식은 `nvme-review-project`, `schemaVersion=1`입니다.
- 파일 자체는 프로젝트에 포함하지 않습니다. JSON과 이름으로 참조한 덤프·캡처·문서를 함께 보관하세요.
- JSON 내보내기를 시도하면 브라우저 다운로드로 전달합니다. 실제 파일 보관 여부는 다운로드 목록에서 확인하세요.
- CSV는 체크리스트 또는 결과 보고서를 내보냅니다. 인쇄는 브라우저 인쇄 기능을 사용합니다. 보고서는 전체 NVMe/OCP 인증 결과가 아닙니다.

## 편집 원본과 재생성

**유일한 편집 원본은 `source/catalog.json`입니다.** `content.json`과 HTML은 빌더 결과물입니다. 과거 Python 편집 모듈은 이관 기록으로만 보존했습니다. 해당 모듈을 수정해도 현재 콘텐츠에는 반영되지 않습니다.

카탈로그 구조:

- `documents`: 버전·파일·SHA-256·공식 출처·확보 날짜.
- `excerpts`: 고정 ID·원문·문서/절/Figure/인쇄·PDF 페이지·분류·대조 상태. 미확인 분류를 자동으로 SHALL 조건으로 확정하지 않습니다.
- `fields` / `psd`: 정의·비트·해석 안내·관계·조건 연결.
- `conditions`: 공유 조건·의무 수준·적용 범위·관측값·요구·예외·원문 조각 ID.
- `coverage`: 필드·비트·각주·PSD 대응과 확인 상태.
- `workflows`: 공유 condition ID를 참조하는 작업 목록.

기존 ID는 문구를 수정해도 유지하세요. 새 항목만 새 ID를 부여합니다. revision은 빌더가 의미·의무 수준·원문·문서 hash로 산출합니다. 조건을 삭제할 때 관련 `check_bindings`와 작업 목록의 참조도 제거해야 합니다. 과거 프로젝트는 별도로 수정할 필요가 없습니다.

```powershell
python build.py
python test_catalog.py
node enhancement_qa.cjs
```

`--refresh-content`는 호환 옵션이며 현재 카탈로그를 컴파일합니다. 기본 생성은 Python 표준 라이브러리만 사용합니다. 원문 신규 추출에는 pypdf/pdfplumber, 브라우저 검사에는 Node.js·Playwright·Edge가 필요합니다. Playwright 경로를 두 번째 인수로 전달할 수 있습니다.

## 근거 범위와 확인 상태

Base 2.1 / NVM Command Set 1.1 / OCP 2.6 및 공식 PCIe Transport 1.1 / NVMe-MI 2.0 / OCP가 지정한 MI 1.2d / IEEE 구성 지침을 버전별로 분리합니다.

외부 원문은 짧은 인용과 한국어 해설을 내장하고, 전체는 로컬 PDF 링크로 확인합니다. PDF는 HTML의 상위 폴더에 둡니다. HTML만 옮겨도 내장 콘텐츠는 읽을 수 있습니다.

IEEE 공개 OUI CSV는 공식 서버가 HTTP 418을 반환해 미확보입니다. 구성 지침 확보와 실제 할당 확인은 다릅니다. 미조회 결과를 미할당으로 판단하지 않습니다. 확보 상태와 시도 날짜는 `source/external_manifest.json`에 있습니다.

FUSES 정의 공백, ANACAP/KPIOC/AWUPF 문구·참조 불일치, 정확히 7 TiB의 NSM-5 경계, 다른 Command Set·보안 인증·고객 자료는 후속 확인 대상으로 유지합니다. 실제 장치 접근·덤프 자동 분석·자동 판정은 없습니다.

## 검사 결과와 인계

- `output/source_coverage.json`: 대응 등록과 의미 대조 상태, 확인 대기 목록.
- `output/validation.json`: 4096-byte 레이아웃·비트·PSD·출처·관계·문서 hash 검사.
- `output/enhancement_validation.json`: 오프라인 전체 필드·참조·6개 작업·프로젝트 저장/복원·이력·개정/삭제·CSV·모바일 검사.
- `output/project_validation.json`: controller/namespace 분리·미반영 입력 이동 취소·필수 관측값·검토자·설정 변경·환산·인쇄·단계 진입 화면 검사.
- `output/stages/stage1~4.json`: 단계별 구현·검증 범위.
- `output/stages/stage1~4.html`: 같은 최종 카탈로그를 사용하는 단계별 진입 화면 스냅샷. 별도 과거 규격 버전이 아닙니다.
- `output/implementation_handoff.md`: 변경·미확인 항목·재생성·검증 인계 기록.
- `output/qa/`: 화면과 왕복 저장 검사용 예제 파일. 실제 장치 결과가 아닙니다.

구조·화면 검사 통과를 모든 원문 해석의 확인 완료로 표현하지 않습니다. 콘텐츠 확인 상태와 제품별 수동 검토 결과는 항상 별도로 관리합니다.

추가 검사: `node project_qa.cjs [Playwright 경로]`. Controller가 다르면 같은 namespace 이름도 별도 기록으로 유지합니다. 조건 만족·위반에는 관측값, 미검토 이외 결과에는 검토자가 필요합니다. 관측 시점과 상태는 입력 전에는 미확인입니다. 적용 설정이 바뀌면 관련 기존 결과에 재확인 필요를 표시합니다.
